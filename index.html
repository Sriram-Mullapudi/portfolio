RETRIEVAL / 01SIMPLIFIED SYSTEM

Query → Vector + full text → RRF → Answer

30K documents. 92% Recall@10. ~1 s p95.

The problem

Find useful answers across a large document collection, while keeping each tenant’s data isolated.

Java 17 / Spring Boot / React / PostgreSQL / pgvector / Redis / AWS / Docker / Terraform

Architecture & decision
Combined pgvector HNSW and PostgreSQL full-text search with Reciprocal Rank Fusion. The two retrieval approaches contribute to one ranked result set.
Engineering challenge
Enforced tenant isolation at API and data-access layers for ~12 tenants, 300–500 users and 4 roles. Validated 35–40 automated authorization/security scenarios.
Outcome
Retrieved across 30K documents and 200K–250K chunks at ~500 ms typical and ~1 s p95 latency. Evaluation on ~200 labelled queries yielded 87% Recall@5, 92% Recall@10 and an 83% acceptable-answer rate for end-to-end RAG responses.
Cloud delivery
Provisioned ECS Fargate, RDS, ElastiCache, ALB and Secrets Manager with Terraform and GitHub Actions. Setup/deployment fell from 2–3 hours to 20–30 minutes, enabling multiple deployments per day when needed.
My contribution
Built and evaluated the hybrid retrieval pipeline, tenant controls and automated AWS delivery.
Design tradeoff
Combining semantic and full-text retrieval adds a ranking step. Recall and answer-quality evaluation make that choice measurable alongside latency.

5K+ real sales. 10K+ SKU catalog. 0 duplicates in tests.

The problem

Support everyday retail workflows on an offline-first system: sales, refunds, inventory, promotions, loyalty and shift reconciliation.

Rust / Tauri 2 / SQLite / React / TypeScript

Architecture & decision
Packaged a Windows application with React and TypeScript, Rust/Tauri 2, and atomic SQLite operations for transaction integrity.
Engineering challenge
Protected financial workflows with RBAC, Argon2 PIN hashing, append-only audit logs and duplicate-payment controls.
Outcome
Tested across a 10K+ SKU catalog and 5K+ real-world sales in a live convenience-store environment. Separately validated 10K+ integrity-test transaction attempts across 20+ failure/concurrency scenarios with zero duplicate charges.
My contribution
Built and packaged the Windows application and validated retail workflows and transaction integrity in a live-store environment and separate failure tests.
Design tradeoff
An offline-first application keeps local transaction integrity central. The validation distinguishes real-world sales from controlled failure and concurrency tests.
